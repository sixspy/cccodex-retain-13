# cc-retain-lab

CC_Codex 二期（26.11）**数据工程**产品线：**留存裁撤台**（FastAPI + 原生 JS SPA + SQLite）。

## 一句话骨架（自有，非外仓抄题）

**分区留存策略版本 → 到期扫描裁决 → 归档或销毁执行 → 策略与实物分区对账**

与现有六线正交（不是采集目录、ETL 管道、同步源、解析入库、编排流、种子摄取）。  
也不碰外仓常见指纹（Feed 归并 / 作业编排 / CDC 游标 / 质检签发 / 贴源-明细-汇总）。

## 领域

- **所属领域**：数据工程  
- **子方向**：数仓与数据湖（分区留存 / 裁撤闭环）

## 技术栈

| 层 | 选型 |
|----|------|
| 后端 | Python 3.12、FastAPI、Uvicorn、SQLite |
| 前端 | 原生 JS 单页（全中文），青灰底 + 铜强调，顶栏导航（非绿侧栏克隆） |
| 测试 | pytest + httpx（本地秒级闭环，优先于 compose） |

## 基线已通主链

1. 现行留存策略（主题域 / 保留天 / 到期动作）  
2. 实物分区列表（在线 / 归档 / 销毁）  
3. 按基准日到期扫描 → 生成待执行裁决  
4. 单条裁决执行（归档写地址 / 销毁清零）  
5. 策略与实物对账报告  

## 入库放行闸口（retain-13）

下游「放行队列」把分区当可消费入库源。分区被销毁后，空分区不得再当入库源，本面补齐闸口：

- **闸口判定与分区态对齐**：仅 `在线 且 row_count>0` 可放行；已销毁空分区 / 空分区 /
  已归档 / 裁撤中一律拦截（误放即拦），拒绝原因与判定时刻分区态写在放行单上，页面直出。
- **留痕方式（择一）**：不另建「拒绝事件表」。拒绝原因、申请快照（分区态/行数）、
  判定分区态、操作人全部留存在 `release_orders` 放行单自身的快照字段，单据即留痕。
- **互斥锁写**：进程内线程锁串行化两名操作员的并发放行，SQLite 侧 `BEGIN IMMEDIATE`
  立即取写锁，事务内对单据状态二次复核——并发同一单只准一笔成功，缺锁双成功会被 409 拦下。
- **整笔退回**：单据状态、快照、闸口留痕同事务落库，中途异常整体回滚，无半截放行。
- **三面同动**：放行队列、分区列表（放行 待/准/拒 计数）、对账详情（放行计数 +
  「悬空待放行」风险明细）共用同一套查询口径。
- 闸口记录全部落本机 SQLite，`入库放行任务可验`：见 `tests/test_release_gate.py`。

预留切口（未做，供后续功能题）：策略换版生效窗、重裁作废、跨域依赖冻结、归档回灌等。
